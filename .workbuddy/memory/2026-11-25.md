### 结论：接口形态
- 端点 `wss://openspeech.bytedance.com/api/v4/ast/v2/translate`，头 `X-Api-Key` +
  `X-Api-Resource-Id: volc.service_type.10053`（+可选 `X-Api-Connect-Id`）。
- protobuf 二进制帧，非 JSON。三条报文：StartSession(100) → TaskRequest(200) 推音频 → FinishSession(102)。
- 下行（`ast2Client`）与上行复用同一个 `AstClient` 类，只是音频来源是 BlackHole 16ch、
  出口是物理耳机；当前用 `mode=s2s` + `zhen/zhen` 双向自动识别，s2s 直接回中文语音流，
  不再过 `tts_client.js` 的独立 SSE TTS。

### 发现并修复的 3 个真 bug（已改代码）
1. **`desktop/protos/ast.proto` ReqParams 字段号错位**（最严重）
   项目写 `is_custom_speaker=5` / `tts_resource_id=6` / `speech_rate=8`；
   官方 ast_service.proto 是 `speech_rate=5` / `enable_source_language_detect=6` /
   `is_custom_speaker=7` / `tts_resource_id=8`。
   → wire 上 `isCustomSpeaker=true` 落到 field5 被服务端读成 `speech_rate=1`；
   `ttsResourceId` 字符串落到 field6(bool varint) 类型冲突被丢弃；
   官方 7/8 从未写过 ⇒ **克隆音色链路一直是失效的**（服务端按默认复刻输入音色跑）。
   已按官方改：ReqParams 重排、Corpus/ResponseMeta(Billing)/TranslateResponse 补齐字段号，
   EventType 加 UpdateConfig=201。
2. **`ast_client.js` requestMeta 字段名大小写**：官方 rpcmeta.proto 用 PascalCase
   （`SessionID`/`ConnectionID`/`Message`），protobufjs 原样保留。项目写成
   `sessionID`/`connectionID` → `T.create()` 静默丢弃 → **session_id 从未发出**。
   已改为 `SessionID`/`ConnectionID`，并修 `SessionFailed` 读 `responseMeta.Message`。
3. 补 `sourceAudio.codec='raw'`（官方要求仅支持 raw）。

### 官方文档要点
- s2s 指定音色模式只支持 2 个公版音色：`zh_female_vv_uranus_bigtts` /
  `zh_male_jingqiangkanye_emo_mars_bigtts`；不传/传错 → 默认复刻输入音频音色。
- `zhen` 需 source_language 和 target_language 同时传；声音复刻模式仅 lang_8。
- pcm 16kHz→16bit int，24kHz→32float；ogg_opus 固定 48kHz 32float。
- `tts_resource_id` 走精品/复刻链路必填，可选 seed-tts-1.0/2.0、seed-icl-1.0/2.0。
- 错误码 20000000 成功；45000001 参数无效；45000002 空音频；45000081 等包超时；
  45000151 音频格式错；55000031 服务繁忙。
- 必须等 SessionStarted(150) 后再发音频；建议 80ms 一包。

## 追加：is_custom_speaker 字段语义 + CLONE_MODE 恢复
- 官方文档确认：is_custom_speaker 默认 false，作用是"是否复刻音色(触发鉴权)"；
  S_... 自定义音色必须 is_custom_speaker=true + tts_resource_id=seed-icl-2.0；
  精品音色(zh_female_vv_uranus_bigtts 等2个公版)/不指定音色 → 不传（false/缺省）。
- 之前误把 CLONE_MODE 三分支收成一行固定 isCustomSpeaker=true+seed-icl-2.0，导致 .env 里
  ARK_CLONE_MODE=3 成死变量。已恢复三分支(1=默认鉴权/2=不鉴权/3=通用复刻 seed-tts-2.0)。
- 三种组合 wire 实测：组合1 f7=1(=true) + f8=seed-icl-2.0；组合3 不含 f7 + f8=seed-tts-2.0。
